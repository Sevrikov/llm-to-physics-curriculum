## ЧАСТИНА 1: КОНЦЕПТУАЛЬНА ОСНОВА

### 1.1 Нова парадигма навчання — «ММА-підхід»

**Стара логіка (поточне ТЗ):**
```
Теорія (40 год) → Практика (код з прикладу) → Зрозумів → Наступна тема
```

**Нова логіка:**
```
БІЙ (запустив, щось зламалось або програв) 
  → ТЕХНІК (конкретний прийом що вирішує проблему)
  → РОЗУМІННЯ (теорія з'являється як пояснення ЧОМУ прийом працює)
  → РЕВАНШ (той самий тип бою але складніший)
```

**Аналогія з бойовими мистецтвами:**
- Не читають книгу «Теорія кидків» перед першим татамі
- Спочатку кидають і падають — потім тренер показує ЧОМУ вийшло/не вийшло
- Кожна техніка виправляє конкретну поразку
- Прогрес вимірюється через спаринг (benchmark), не через тест знань

### 1.2 Одиниці вимірювання прогресу

| Рівень | Що вимірюється | Формат атестації |
|--------|---------------|-----------------|
| Кожна тема | Score на конкретному eval | Автоматичний |
| Кожен пояс | Benchmark vs стандартний суперник | «Турнірний матч» |
| Вся програма | Система в продакшні з вимірюваним покращенням | End-to-end тест |

### 1.3 Концептуальний вектор програми

```
РІВЕНЬ 1-4: Text Intelligence
  └─ Навчитись маніпулювати мовними моделями як інструментом

РІВЕНЬ 5-6: Perceptual + Embodied Intelligence  
  └─ Модель що бачить, діє в симульованому світі, передбачає наслідки

РІВЕНЬ 7: Future Intelligence Substrate
  └─ Розуміння наступного покоління обчислювального заліза
     (нейроморфне, мемристорне, фотонне)
```

### ⬜ БІЛИЙ ПОЯС — «Учень API»
**Тривалість:** 4 тижні / 160 годин
**Суперник для атестації:** GPT-4o з нульовим контекстом (no system prompt)
**Ціль атестації:** Побудована prompt-система набирає >= 7.0/10 на eval set, без fine-tuning

#### Прогалина з поточного ТЗ
Поточне ТЗ починає з `conda install` і теорії трансформерів. Студент не розуміє НАВІЩО це все поки не побачить задачу. Новий підхід: день 1 — запустив, порівняв, побачив gap.

#### Структура

**[ПЕРШИЙ БІЙ] — День 1-2 (без теорії)**

- Практичний кейс «Сліпе порівняння» (4 год)
  - Взяти 20 реальних задач з обраної ніші
  - Запустити GPT-4o, Claude Sonnet, Qwen-7B через Ollama
  - Зафіксувати: де кожна модель провалилась і чому (власна гіпотеза студента)
  - Артефакт: `baseline_battle_report.md` — це буде еталон для всього курсу

- Практичний кейс «Зламай промпт» (4 год)
  - Взяти working приклад промпту → знайти 5 способів його зламати
  - Виявити: injection, переключення мови, граничні випадки, ambiguity
  - Артефакт: `prompt_failure_catalog.jsonl`

**[ТЕХНІКИ ПОЯСУ]**

- Техніка 1: «Системний промпт як конституція» (8 год)
  - Що: ієрархія інструкцій (system > few-shot > user)
  - Кейс: побудувати 10 варіантів системного промпту → автоматичний benchmark
  - Benchmark метрика: score на 50 eval прикладах (LLM-judge)
  - Теорія після: чому порядок інструкцій важливий, attention patterns

- Техніка 2: «Few-shot як демонстрація стилю» (8 год)
  - Що: навчити модель нового формату без fine-tuning
  - Кейс: специфічний вивід (таблиця, JSON, медичний протокол) через приклади
  - Benchmark метрика: format compliance rate на 100 запитах

- Техніка 3: «Chain-of-thought як декомпозиція» (8 год)
  - Що: явне мислення вголос покращує точність на складних задачах
  - Кейс: задача з 3+ кроками → direct vs CoT → виміряти delta
  - Теорія після: чому CoT працює (intermediate computation в attention)

- Техніка 4: «Structured output як контракт» (8 год)
  - Що: надійний JSON-вивід з retry логікою
  - Кейс: побудувати парсер що ніколи не падає на malformed JSON
  - Артефакт: reusable `robust_json_caller.py`

- Техніка 5: «Cost-quality Pareto» (8 год)
  - Що: та сама задача через різні моделі — де cost/quality перетинаються
  - Кейс: побудувати routing логіку (прості запити → дешева модель, складні → дорога)
  - Артефакт: `model_router.py`

**[ТЕОРІЯ — після практики]**
- Tokenization (після того як студент помітив що «слова» рахуються дивно)
- Context window limits (після першого overflow)
- Temperature/sampling (після першого нестабільного виводу)
- Ресурс: Karpathy «Intro to LLMs» (YouTube, 1 год) — дивитись після 2 тижнів практики

**[АТЕСТАЦІЯ БІЛОГО ПОЯСУ]**
- Завдання: prompt-система для своєї ніші, без fine-tuning
- Критерій: LLM-judge score >= 7.0/10 на 50 eval прикладах
- ROI перевірка: скільки коштує 1000 запитів в твоїй системі vs GPT-4o з нульовим промптом

### 🟡 ЖОВТИЙ ПОЯС — «Майстер даних»
**Тривалість:** 6 тижнів / 240 годин
**Суперник:** Власна модель після SFT на поганому датасеті (навчитись відрізняти)
**Ціль:** Зібраний датасет 2000+ прикладів, LLM-judge score датасету >= 8.0/10

#### Прогалина з поточного ТЗ
Фази 1-3 навчають Python і збір даних окремо. Тут вони об'єднані навколо принципу: **якість даних визначає стелю моделі**.

#### Структура

**[ПЕРШИЙ БІЙ РІВНЯ]**
- Кейс «Два датасети — одна модель» (16 год)
  - Взяти 3 різних публічних датасети схожої тематики (HuggingFace)
  - Fine-tune (мінімальний, 1 епоха) на кожному
  - Порівняти результати → усвідомлення: дані важливіші за архітектуру
  - Артефакт: `dataset_comparison_report.md`

- Кейс «Отруєний датасет» (8 год)
  - Навмисно додати 5% поганих прикладів
  - Виміряти деградацію якості
  - Знайти «отруєні» через loss spike аналіз
  - Теорія після: чому нейромережі чутливі до outlier прикладів

**[ТЕХНІКИ ПОЯСУ]**

- Техніка 1: «Python-стек для даних» (24 год)
  - Numpy, Pandas, asyncio, JSONL формат
  - Кейс: написати pipeline збору даних з асинхронними API викликами
  - Ресурс: переноситься з Фази 1 поточного ТЗ (tasks 1-P1, 1-P2)

- Техніка 2: «HuggingFace datasets ecosystem» (16 год)
  - load_dataset, filter, map, concatenate
  - Кейс: знайти 3+ датасети близьких до ніші → злити в один → ConversionPipeline
  - Ресурс: HF Course Chapter 5

- Техніка 3: «Self-instruct pipeline» (24 год)
  - Що: GPT-4o генерує різноманітні задачі → розширення датасету
  - Кейс: 50 seed прикладів → 500 через self-instruct → перевірити diversity
  - Ресурс: переноситься з Фази 3 поточного ТЗ (task 3-P2)

- Техніка 4: «Semantic deduplication» (16 год)
  - Що: cosine similarity через embeddings → прибрати дублі
  - Кейс: виміряти наскільки датасет «різноманітний» до і після
  - Ресурс: sentence-transformers, алгоритм greedy dedup

- Техніка 5: «LLM-judge калібрація» (16 год)
  - Що: LLM-judge може помилятись — треба перевірити correlation з human
  - Кейс: 50 прикладів оцінити вручну + через LLM-judge → Cohen's kappa
  - Ключове: виявити систематичні сліпі плями судді

- Техніка 6 [НОВА]: «Синтетична фізична сцена» (24 год)
  - Що: перший місток до рівнів 5-6
  - Кейс: генерувати текстові описи фізичних ситуацій через GPT-4o
  - Верифікація: перевірити генеровані сценарії через простий симулятор (MuJoCo/Genesis)
  - Виявити: де LLM «знає» фізику (текст правдивий) але де галюцинує числа
  - Ресурс: Genesis quickstart (Python, 2-3 год на встановлення)

**[ТЕХНІЧНИЙ БАЗИС — PyTorch та архітектура]**
- PyTorch тензори і autograd (16 год) — Karpathy nanoGPT відео
- Токенізація і chat template — КРИТИЧНО для fine-tuning
- Attention візуалізація — після того як студент побачив перший eval

**[АТЕСТАЦІЯ ЖОВТОГО ПОЯСУ]**
- 2000+ прикладів у `data/train_sft.jsonl`
- LLM-judge score на 10% вибірці >= 8.0/10
- Semantic deduplication пройдена (cosine < 0.92)
- Документовано джерело кожного прикладу

### 🟤 КОРИЧНЕВИЙ ПОЯС — «Архітект світів»
**Тривалість:** 10 тижнів / 400 годин
**Новий матеріал:** 100%
**Суперник:** Text-only плануючий LLM
**Ціль:** World model передбачає траєкторію з похибкою < порогу, LLM+WM б'є чистий LLM на задачах планування

#### Концептуальний стрибок (важливо пояснити)

```
TEXT LLM:
"Якщо штовхнути м'яч під кутом 30° — він полетить по параболі"
→ Знання з тексту. Асоціація. Немає числа.

WORLD MODEL:
state_t = [x=0, y=1, vx=5, vy=3, mass=0.5]
action = [force_x=2, force_y=0]
state_t+1 = model.predict(state_t, action)
→ [x=0.15, y=1.2, vx=5.4, vy=2.7]
→ Симуляція. Каузальність. Конкретне число.
```

**Важливий disclaimer для студентів:**

- Техніка 4: «Мемристорні crossbar arrays» (40 год)
  - **⚠️ MemTorch ВИДАЛЕНО** — abandoned з 2021, не сумісний з PyTorch 2.0+
  - **Замінити на AIHWKIT** (IBM Analog Hardware Acceleration Kit) — підтримується, стабільний
    - `pip install aihwkit`
    - Симулює RRAM/PCM crossbar arrays з реалістичними шумовими моделями
    - Повна сумісність з PyTorch
  - Кейс 1: `AnalogLinear` замість `nn.Linear` → виміряти accuracy degradation під analog noise
  - Кейс 2: hardware-aware training з analog optimizer (SGD з drift compensation)
  - Кейс 3: inference energy simulation — crossbar vs GPU FLOPS
  - Ресурс: ibm.github.io/aihwkit, paper «Analog hardware-aware training» (IBM, 2021)
  - **Ключовий insight:** аналогові обчислення = matrix-vector multiply «безкоштовно» по енергії → inference без пересилання даних

- Техніка 5: «In-memory computing / PIM» (40 год)
  - **Фреймворк:** IBM Analog Hardware Acceleration Kit (AIHWKIT)
    - `pip install aihwkit`

    - Hardware-aware training з реалістичними шумовими моделями
  - Кейс 1: навчити ResNet-18 через analog-aware optimizer → порівняти з digital
  - Кейс 2: inference energy simulation — crossbar vs GPU FLOPS
  - Ресурс: ibm.github.io/aihwkit, paper «Analog hardware-aware training» (IBM, 2021)

- Техніка 6: «Spiking Neural Networks» (48 год)

    - Складніше встановлення, але є software emulator без реального чипа
  - Кейс 1: SNN для MNIST — ANN-to-SNN conversion → порівняти accuracy

  - Теоретична частина:
    - Оптичний dot product через Mach-Zehnder interferometer
    - Матричне множення в оптичному домені (O(1) час, c швидкість)
    - Компанії: Lightelligence, Luminous Computing, Lightmatter Envise
  - Практична частина (обмежена):

    - Моделювання noise в оптичному домені
    - Порівняти теоретичну енергетику: optical vs digital matrix multiply
  - Ресурс: Lightmatter whitepaper, paper «Reprogrammable electro-optic nonlinear activation functions» (NeurIPS 2020)
  - **Ключовий insight:** швидкість світла + паралельна обробка = inference на терагерцових частотах

- Техніка 8: «Квантовий ML — ознайомлення» (24 год)

  - Чесна оцінка: quantum advantage в ML ще не досягнуто для реальних задач
  - **Ключовий insight:** квантова заплутаність = exponential state space → теоретично для комбінаторних задач
