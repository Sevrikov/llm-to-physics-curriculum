## 📖 Теорія (10 хвилин)

### Чому показувати краще ніж пояснювати

Системний промпт пояснює **словами** як відповідати. Few-shot **показує** на прикладах.

Аналогія: "Пиши формально, структуровано, з посиланнями на закони" (слова) vs показати 2 ідеальні відповіді (приклади). Мозок — і людський, і трансформерний — краще вчиться на демонстрації.

```python
# Zero-shot: тільки інструкція
messages = [system, user_question]

# Few-shot: інструкція + приклади + питання
messages = [
    system,
    {"role": "user",      "content": "Приклад питання 1"},
    {"role": "assistant", "content": "Ідеальна відповідь 1"},
    {"role": "user",      "content": "Приклад питання 2"},
    {"role": "assistant", "content": "Ідеальна відповідь 2"},
    {"role": "user",      "content": "Реальне питання"},
]
```

Важливо: модель не оновлює свої ваги. Few-shot — це **in-context conditioning**, а не навчання. Після закриття сесії — забуває.

### Два застосування few-shot

1. **Навчити формату** — якщо потрібен специфічний вивід (таблиця, JSON, структура)
2. **Навчити OOD-відмові** — показати на прикладі як правильно відмовляти

### Три типи прикладів (і чому негативні — особливо цінні)

Більшість новачків пишуть тільки "правильні" приклади. Але показуючи **як НЕ треба** — ти явно звужуєш простір неприйнятних відповідей. Модель вчиться і з позитивних, і з негативних взірців.

```
Позитивний приклад → модель знає що бажано
Негативний приклад → модель знає що неприйнятно
Near-miss приклад  → модель розуміє тонку межу
```

## 💻 Практика: `04_few_shot_lab.py`

```python
# experiments/04_few_shot_lab.py
import ollama

SYSTEM = """Ти юридичний асистент по трудовому праву України.
Відповідай тільки у вказаному форматі."""

def ask_zero_shot(question: str) -> str:
    resp = ollama.chat(
        model='qwen2.5:7b',
        messages=[
            {'role': 'system', 'content': SYSTEM},
            {'role': 'user',   'content': question},
        ],
        options={"temperature": 0},
    )
    return resp['message']['content']


FEW_SHOT_EXAMPLES = [
    # --- Позитивний приклад 1: правильний формат ---
    {'role': 'user', 'content': 'Скільки днів щорічної відпустки?'},
    {'role': 'assistant', 'content': (
        "**📋 Правова норма:** ст. 75 КЗпП України\n"
        "**Мінімум:** 24 календарних дні на рік\n"
        "**Особливі категорії:** неповнолітні — 31 день, педпрацівники — 56 днів\n"
        "**Практично:** Частина відпустки ≥ 14 днів безперервно\n"
        "**Рівень впевненості:** Впевнений ✅"
    )},

    # --- Негативний приклад: показуємо як НЕ треба відповідати ---
    # Це "антиприклад" — явно позначений. Модель бачить: ось що неприйнятно.
    {'role': 'user', 'content': '[ПОГАНИЙ ПРИКЛАД — НЕ НАСЛІДУЙ] Скільки відпустки?'},
    {'role': 'assistant', 'content': (
        "[ПОГАНО] Зазвичай близько місяця, залежить від компанії і домовленості. "
        "Краще уточніть у відділі кадрів.\n"
        "# Чому це погано: немає статті, немає точної цифри, немає рівня впевненості — "
        "така відповідь марна для користувача."
    )},

    # --- Позитивний приклад 2: правильна OOD відмова ---
    {'role': 'user', 'content': 'Як мені відкрити ФОП?'},
    {'role': 'assistant', 'content': (
        "Це питання виходить за межі моєї спеціалізації (трудове право).\n"
        "ФОП — реєстрація бізнесу, не трудові відносини.\n"
        "**Рекомендую:** бухгалтер або юрист по господарському праву."
    )},
]


def ask_few_shot(question: str) -> str:
    resp = ollama.chat(
        model='qwen2.5:7b',
        messages=[
            {'role': 'system', 'content': SYSTEM},
            *FEW_SHOT_EXAMPLES,
            {'role': 'user', 'content': question},
        ],
        options={"temperature": 0},
    )
    return resp['message']['content']


test_questions = [
    "Роботодавець затримав зарплату на 2 тижні.",
    "Мене скорочують. На що я маю право?",
    "Чи можна звільнити під час лікарняного?",
    "Мій начальник — нікчема. Що робити?",  # OOD тест
    "Де найближчий нотаріус?",              # OOD тест
]

print("ПОРІВНЯННЯ: Zero-shot vs Few-shot (з негативним прикладом)\n")
for q in test_questions:
    print(f"\n{'='*60}")
    print(f"ПИТАННЯ: {q}")
    print(f"\n--- ZERO-SHOT ---")
    print(ask_zero_shot(q)[:350])
    print(f"\n--- FEW-SHOT ---")
    print(ask_few_shot(q)[:350])
```

## 🔬 Експеримент: скільки прикладів оптимально?

"4-5 прикладів" — популярна евристика, але у різних ніш різний sweet spot. Перевір сам:

```python
# experiments/04_shot_count_experiment.py
"""
Порівнюємо 0-shot, 1-shot, 3-shot, 5-shot на eval set.
Шукаємо sweet spot: де якість зростає, де plateau.
"""
import ollama
import json

SYSTEM = """Ти юридичний асистент по трудовому праву України."""

# Всі доступні приклади (максимум що маємо)
ALL_EXAMPLES = [
    {'role': 'user', 'content': 'Скільки днів відпустки?'},
    {'role': 'assistant', 'content': '**Норма:** ст. 75 КЗпП — 24 дні. **Впевненість:** Висока ✅'},
    {'role': 'user', 'content': 'Затримка зарплати — що робити?'},
    {'role': 'assistant', 'content': '**Норма:** ст. 115 КЗпП — виплата 2× на місяць. **Кроки:** 1) Письмова вимога 2) Держпраці 3) Суд. **Впевненість:** Висока ✅'},
    {'role': 'user', 'content': 'Можна звільнити на лікарняному?'},
    {'role': 'assistant', 'content': '**Норма:** ст. 40 КЗпП — ЗАБОРОНЕНО звільнення під час хвороби (крім ліквідації). **Впевненість:** Висока ✅'},
    {'role': 'user', 'content': 'Як оскаржити незаконне звільнення?'},
    {'role': 'assistant', 'content': '**Норма:** ст. 235 КЗпП — суд, 1 місяць на подачу. **Кроки:** 1) Копія наказу 2) Позов до суду 3) Вимога поновлення + компенсація. **Впевненість:** Висока ✅'},
    {'role': 'user', 'content': 'Яка вихідна допомога при скороченні?'},
    {'role': 'assistant', 'content': '**Норма:** ст. 44 КЗпП — мінімум 1 місячний середній заробіток. **Впевненість:** Висока ✅'},
]

# Eval set — питання для виміру якості
EVAL_QUESTIONS = [
    "Чи законна робота без трудового договору?",
    "Скільки лікарняних оплачується?",
    "Що таке матеріальна відповідальність?",
    "Можна відмовитись від понаднормових?",
    "Куди скаржитись на роботодавця?",
]

def simple_score(answer: str) -> float:
    """Базова евристика якості: є стаття + є кроки + є впевненість."""
    score = 0.0
    if any(kw in answer for kw in ["ст.", "КЗпП", "стаття", "закон"]):
        score += 0.4
    if any(kw in answer.lower() for kw in ["кроки", "дії", "1)", "по-перше"]):
        score += 0.3
    if "впевненість" in answer.lower() or "✅" in answer:
        score += 0.3
    return score

results = {}
shot_configs = [
    (0, []),
    (1, ALL_EXAMPLES[:2]),   # 1 приклад = 2 повідомлення
    (3, ALL_EXAMPLES[:6]),   # 3 приклади
    (5, ALL_EXAMPLES[:10]),  # 5 прикладів
]

for n_shots, examples in shot_configs:
    scores = []
    for q in EVAL_QUESTIONS:
        messages = [{'role': 'system', 'content': SYSTEM}]
        messages.extend(examples)
        messages.append({'role': 'user', 'content': q})

        resp = ollama.chat(
            model='qwen2.5:7b',
            messages=messages,
            options={"temperature": 0},
        )
        scores.append(simple_score(resp['message']['content']))

    avg = sum(scores) / len(scores)
    extra_tokens = n_shots * 120  # приблизно токенів на приклади
    results[f"{n_shots}-shot"] = {"avg_score": round(avg, 2), "extra_tokens": extra_tokens}
    print(f"{n_shots}-shot: score={avg:.2f} | +{extra_tokens} токенів на запит")

print("\n→ Де score перестає рости? Це твій sweet spot.")
```

**Типовий результат:**
```
0-shot: score=0.35 | +0 токенів на запит
1-shot: score=0.62 | +120 токенів на запит
3-shot: score=0.78 | +360 токенів на запит
5-shot: score=0.79 | +600 токенів на запит   ← plateau, не варто
```
3 приклади дають 95% вигоди від 5 за меншу вартість.

## ⚠️ Типові помилки

| Помилка | Реальність |
|---------|-----------|
| "Few-shot = модель навчається" | Модель не оновлює ваги. Після сесії — все забуде |
| "Більше прикладів = краще" | >5 прикладів часто dilute system prompt. Є plateau |
| "Тільки ідеальні приклади" | Near-miss і негативні приклади вчать краще — показують межу |
| "Few-shot замінює fine-tuning" | Для 1000+ стабільних сценаріїв потрібен fine-tuning (Orange Belt) |
